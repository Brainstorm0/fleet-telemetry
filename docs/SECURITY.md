# Cloud Security - Concerns and Mitigations

| Threat | Mitigation in this project |
|---|---|
| Device impersonation | Each simulator uses an **X.509 certificate** issued by AWS IoT Core. The IoT policy lets it connect only with its own client ID and publish only to `fleet/telemetry/*` (least privilege). |
| Data tampering in transit | Every frame carries an **HMAC-SHA256 signature**. The Lambda recomputes it with a shared secret (`hmac.compare_digest`, constant time) and rejects mismatches. Try `--tamper-rate 0.1` in the simulator to see it. |
| Eavesdropping | MQTT over **TLS 1.2** (port 8883), all AWS APIs over HTTPS, the dashboard is only reachable over HTTPS (API Gateway endpoints are TLS-only; with CloudFront enabled, minimum **TLSv1.2_2021** and HTTP redirected to HTTPS). |
| Data at rest | Kinesis encrypted with KMS (`alias/aws/kinesis`), DynamoDB server-side encryption with KMS, S3 SSE-AES256 (source files versioned in git). |
| Public bucket leaks | S3 **Block Public Access** fully on and no bucket policy. Only the `dashboard-site` Lambda reads it, and only an **allow-list** of four file names (no path traversal, no listing). |
| Over-privileged compute | Production would use one IAM role per Lambda. *Learner Lab blocks role creation, so the provided `LabRole` is used. This is documented as a lab limitation.* |
| Denial of service / abuse | API Gateway throttling (WebSocket 50 rps / burst 100, HTTP 20 rps / burst 50). IoT Core per-account limits. Kinesis absorbs bursts. |
| Cross-site scripting | The dashboard writes all data with `textContent`, never `innerHTML`. The site Lambda adds security headers (HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy). |
| Malformed / poison messages | Schema and range validation; undecodable records are dropped and counted (`InvalidFrame` metric) instead of blocking the shard. |
| Detecting attacks | `InvalidSignature` custom metric + CloudWatch alarm -> SNS email. |
| Secret handling | HMAC secret generated by Terraform (`random_password`) and written only to the git-ignored `simulator/generated/`. Certificates and keys are also git-ignored. *Production improvement: store the secret in AWS Secrets Manager or SSM Parameter Store (SecureString).* |
| Supply chain | CI runs flake8, ESLint, pytest, `terraform validate` and tflint on every pull request. |
| Network segregation | IoT Core is the only device entry point. No VMs, no open SSH ports, no public databases. |
